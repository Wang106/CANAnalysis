# GB/T 27930—2015 离线分析

本页只服务 `/gbt27930` 的本地日志分析。它不连接车辆，不发送报文，也不声明协议一致性或实物兼容。

## 版本

采用 GB/T 27930—2015《电动汽车非车载传导式充电机与电池管理系统之间的通信协议》。

- 标准身份、发布日期 2015-12-28、实施日期 2016-01-01，以及它对 GB/T 27930-2011 的替代关系，见全国标准信息公共服务平台：<https://std.samr.gov.cn/gb/search/gbDetailed?id=71F772D80B0CD3A7E05397BE0A0AB82A>
- 该条目记录 2015 版已于 2024-04-01 废止，并由 GB/T 27930-2023 代替。本次实现仍按用户确认的 2015 版做离线分析，不把 2015 写成当前有效标准，也不混入 2011 或 2023 的报文布局。
- 本次没有取得标准出版社正文。报文编号、长度、周期、单位和字节序采用两份互相一致的公开转述，而不是凭记忆补全：
  - <https://canfd.net/gbt27930.html>
  - <https://github.com/MisakaMikoto128/GBT27930-Sim/blob/main/charger/protocol_tables.py>

两份资料不一致、或只有一份资料写到的字段，不在页面里显示为已解码值。

## 本次解码

地址按上述资料：充电机 `0x56`，BMS `0xF4`。PGN 按 PDU1 取 PF，数据按小端，物理值按 `raw × scale + offset`。

已解码的单帧：CHM、BHM、CRM、CML、BRO、CRO、BCL、CCS、BSD、CSD。

多包重组使用日志中已经出现的 BAM，以及 RTS/CTS/EOM。本页不发送 CTS 或确认。BCP（13 字节）和 BCS（9 字节）在收齐声明长度后才解码；末包可以短于 7 字节，非末包必须是 7 字节。BCS 的单体电压与组号按资料中的 12 位加 4 位打包解释。BRM、时间同步 CTS、BSM、BST、CST、BEM、CEM 仍只按报文代号识别，位域没有逐位核对，不解码字段。

ZLG CANTest 文本按表头读取。时间默认用 0.1 ms/计数，这是对照公开周期作出的推测，并处理 32 位计数回绕。读出 0 帧时页面会说明原因。源地址不是 `0x56` 或 `0xF4` 的帧单独列出。声明长度之后若全是 `FF`，按声明长度处理并注明填充。电流为负时注明负值表示充电方向。会话在重新出现 CHM，或相邻主节点帧间隔超过 5 秒时切开；中止和错误报文不并进阶段串。

合成样例不等于真实设备兼容。

BCL 与 CCS 相邻间隔超过资料所述的 1 秒时给出观察项。5 秒默认超时和完整充电状态机没有实现，页面不会据此给出故障结论。

## 明确未支持

- BMV、BMT、BSP 的变长内容。
- RTS/CTS、端到端应答和中止等非 BAM 传输。未重组完成的多包不会显示为解码成功。
- CTS 的 BCD 时间，以及 BSM、BST、CST、BEM、CEM 的位域。这些报文只识别，不显示物理量。
- GB/T 27930-2011 与 GB/T 27930-2023。
- 内置完整 DBC。没有被上述规则覆盖的字节保持未知。

BHM 的公开资料在正文里写过“字节 0～2”，报文表长度却是 2 字节。解码只接受 2 字节，不把第 3 字节猜成电压的一部分。

# SAE J1939-21 基础离线分析

本页只服务 `/j1939` 的本地日志分析。它不连接车辆，不发送报文，也不声明协议一致性或实物兼容。

## 依据

没有把 SAE 标准正文放进仓库。本次使用的公开资料是：

- Linux 内核文档 [J1939](https://docs.kernel.org/networking/j1939.html)：29 位标识符分为优先级、PGN 和源地址；PGN 内含保留位、数据页、PF 和 PS。PF 小于 240 时是 PDU1，PS 是目的地址且不属于 PGN；PF 大于或等于 240 时是 PDU2，PS 是组扩展并属于 PGN。经典传输最多 1785 字节。广播目的地址使用全局地址 255。广播传输不需要接收方，单播传输才需要接收方确认。
- Linux `net/can/j1939/transport.c`：TP.CM 是 PGN `0xEC00`，TP.DT 是 PGN `0xEB00`。控制字节 BAM 为 `0x20`，RTS 为 `0x10`，CTS 为 `0x11`，End of Message ACK 为 `0x13`，Abort 为 `0xFF`。ISO 11783 ETP 使用 `0x14` 到 `0x17`，本次不重组。
- [CSS Electronics 对 J1939-21 TP 的说明](https://canlogger.csselectronics.com/tools-docs/decoders_mf4/transportprotocol/j1939tp.html)：BAM/RTS 的长度、包数和 3 字节 PGN 位置，以及 TP.DT 的序号加 7 字节数据，并给出 PDU2 BAM 示例。该示例只用于合成夹具，不是本仓库采集的实车日志。

这三处对上述字节位置一致。J1939DA 的商用 PGN/SPN 名称、单位和比例没有可靠的可再分发来源，因此未知 PGN 只显示编号和原始字节。

## 本次行为

单帧显示优先级、保留位、数据页、PF、PS、源地址和归一后的 PGN。PDU1 的全局目的地址 255 显示为“全局”，不进入 PGN。

BAM 与 GB/T 27930—2015 页面共用 `public/can/j1939.mjs`。2015 页面仍按源地址匹配会话，诊断语句保持不变。J1939 页面按源地址加目的地址区分同时进行的会话。声明长度必须在 1 到 1785 之间，包数必须等于按每包 7 字节向上取整的结果；序号要收齐，重复序号保留先出现的数据。未满足这些条件时不显示为重组成功。

RTS 只重组日志里已经出现的数据帧。页面不会生成 CTS、确认或任何其他帧。即使数据帧被拼齐，也单独说明这不表示握手完成。CTS 和 End of Message ACK 只作为观察项。

## 未支持

- J1939DA 信号名、单位和比例。
- J1939-22 和 ASC 里的 CAN FD。超过 8 字节的经典帧也不按 J1939-21 解码。
- ISO 11783 ETP。
- 11 位标准帧。它们被标出，但不判为 J1939 故障。
- 任何发送或总线控制。

## 样本

`tests/fixtures/j1939/session-synthetic.asc` 是合成夹具，文件内已标明。它覆盖不了实车时间、地址声明和厂商报文。有脱敏的真实日志之后，才能做差异核对。

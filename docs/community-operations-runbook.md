# 社区功能运维手册

## 每次发布

1. 运行全部静态、Worker、浏览器测试。
2. 在 preview 应用未执行的迁移并完成冒烟测试。
3. 记录 production Time Travel bookmark。
4. 执行 production 迁移，再发布向后兼容的 Worker。
5. 验证健康接口、注册、登录、评论和管理员后台。
6. 观察错误率、Queue 和 DLQ 至少十五分钟。

## 备份与恢复

- D1 Time Travel：免费档7天、付费档30天。
- 每日导出 D1 到私有备份 Bucket；周备份保留12周，月备份保留12个月。
- 备份 Bucket 使用独立写入凭证，普通 Worker 无删除权限。
- 每季度在隔离恢复环境执行一次恢复演练。
- 恢复生产数据库前记录当前 bookmark；恢复是覆盖操作，需要管理员再次验证并人工确认。

## 告警

- API 五分钟 5xx 超过5%。
- Queue 积压超过100或 DLQ 出现任意消息。
- 邮件连续失败10次或退信率异常。
- 登录失败、注册、评论或上传量异常突增。
- D1/R2/Workers 使用量达到预算的70%、90%、100%。
- 每日备份、导出清理或定时任务失败。

## 邮件故障

评论继续保存；Outbox 保留任务；Queue 重试并转入 DLQ；后台展示失败数。邮箱验证和密码重置明确提示暂不可用，不得绕过验证。恢复后按幂等键重放失败任务。
